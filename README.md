# jpdias.me — personal site

Source for my personal website and blog, live at **[jpdias.me](https://jpdias.me)**.

Built with [Jekyll](https://jekyllrb.com/) 4.x and served via GitHub Pages. Posts are written in Markdown, the look is driven by a small custom layout set under `_layouts/` and styled from `css/`. Icons come from [Remix Icon](https://remixicon.com/) (and a few from [Academicons](https://jpswalsh.github.io/Academicons/) for academic profiles).

## What's here

- `index.md` — landing page (about + recent talks/publications)
- `notes/` — the blog, paginated at `/notes/`, sourced from `_posts/`
- `publications.md` — full publications list (journals + conferences)
- `talks.md` — talks
- `contact.md` — email and social/academic links
- `_posts/` — Markdown blog posts (`YYYY-MM-DD-title.md`)
- `_drafts/` — unpublished posts
- `_data/` — `publications.yml` and `talks.yml` data files
- `_layouts/`, `_includes/` — Liquid templates
- `css/`, `js/`, `fonts/`, `images/` — assets
- `images/favicon/` — favicons, app icons and the default share image (`webprofile-window.png`)
- `CNAME` — custom domain (`jpdias.me`)
- `.well-known/` — domain verification files
- `feed.xml` — RSS feed

## Local development

Requirements: Ruby + Bundler for the site, Node + npm for front-matter linting.

```bash
bundle install
npm install
bundle exec jekyll serve --livereload
```

Then open <http://localhost:4000>. A build output is written to `_site/`.

## Writing a new post

Create a file under `_posts/` named `YYYY-MM-DD-slug.md`:

```markdown
---
layout: post
title: "Short, descriptive title"
date: 2026-07-23 10:00:00 +0000
categories: [notes]
image: /images/some-folder/photo.jpg
description: "One or two sentences for search results and social cards."
---

Body in Markdown.

<!--more-->
```

The `<!--more-->` marker sets the excerpt shown on the index/notes page. Drafts go in `_drafts/` (filename without a date) and are only rendered if you run `jekyll serve --drafts`.

`image` and `description` are required on every post, and posts without them fail validation. Use an image under `/images/`, ideally landscape, at least 600×315 and no smaller than 200×200 (1200×630 is the sweet spot for social cards). Pages without an explicit `image` fall back to `/images/favicon/webprofile-window.png` via front-matter defaults in `_config.yml`. Open Graph, Twitter Card and JSON-LD metadata are generated by [jekyll-seo-tag](https://github.com/jekyll/jekyll-seo-tag).

## Validation

Front matter is validated against the JSON schemas in `schemas/` with [remark-lint-frontmatter-schema](https://github.com/JulianCataldo/remark-lint-frontmatter-schema). The site is then built and checked with [HTMLProofer](https://github.com/gjtorikian/html-proofer) for broken internal links and missing images:

```bash
npm run validate
```

The individual steps are also available as `npm run lint:frontmatter`, `npm run build` and `npm run test:links`.

A pre-commit hook runs the same checks and blocks the commit on errors. Enable it once per clone:

```bash
git config core.hooksPath .githooks
```

The same commands run in CI (`.github/workflows/validate.yml`). Make the **Validate content** check required in branch protection to block pull requests.

## Configuration

Site-wide settings live in `_config.yml`:
- `title`, `description`, `url`, `baseurl`, `username`
- `author`, `logo` — used by `jekyll-seo-tag` for social cards and JSON-LD
- `defaults` — per-page defaults, including the fallback share image
- `default_og_image` — fallback share image used by `feed.xml`
- `nav` — top navigation entries
- `social` / `academic` — icon-link lists rendered on `contact.md`
- `paginate` — posts per page on `/notes/`

## Deployment

Push to `master` and GitHub Pages publishes it. The `CNAME` file pins the custom domain `jpdias.me`.
